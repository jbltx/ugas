[Fixed] Schemas, spec, and the `ugas-schema-author` skill — swept out a family of stale descriptions that contradicted the normative modifier pipeline (§5.3). Three classes of defect: two described `Multiply` as taking a raw *factor* rather than the signed bonus the pipeline actually applies, and one described channel aggregation backwards.

**Inverted `Multiply` convention.** The `Modifier.Operation` description in `gameplay_effect.json`/`.yaml` told consumers to use a "reciprocal magnitude (e.g. `0.5`)" in place of a Divide operation. `Multiply` magnitudes are signed bonuses aggregated as `(1 + Σm)`, so `0.5` is a *+50% bonus* — a consumer following the description to halve an attribute would have increased it by 50%, silently and without a validation error. §9.4.1 already specified `−0.5`. Both schema copies now state the signed-bonus convention with that example, and note that on an `Instant` effect a `Multiply` scales the Base Value by `(1 + magnitude)` with no channel grouping, so magnitude `0` is the identity (§5.2).

**`Channel` omission described backwards.** Both schemas said a modifier with no `Channel` "defaults to the global channel". The normative rule (§5.3, and §9.4's own doc comment) is the opposite: it becomes its own implicit *singleton*, contributing independently. The distinction is material — two channel-less `+0.5` modifiers yield ×2.25, not ×2.0. Also corrected the cross-reference from §16.3 (the ARPG case study) to §5.3 Channel Aggregation.

**Stale 8-step pipeline numbering.** The schema descriptions and the §9.4 TypeScript doc comment numbered `Multiply` 6, `AddPost` 7, `Override` 8 — a fossil of a defunct formulation with a separate "additive percentage" stage. The normative §5.3 Order of Operations and the §9.4.1 table both say 4/5/6; every source now agrees. The §5.3 worked example was itself still built on that defunct model (inputs labelled "Additive Percentage" — never an operation — and "Multiplicative 1: 1.5×" as raw factors) and has been rewritten to demonstrate real channel aggregation, arriving at the same 487.5. The `SPEC.adoc` notation glossary no longer defines an unused `p` "percentage modifier magnitude", and `m` is now described as a signed bonus.

The `Operation` enum values were correct throughout and are unchanged; no gameplay data needed edits (the genre packs already used signed magnitudes).

Also fixes the bundled `ugas-schema-author` simulator, which implemented the stale model in runnable code: the modifier pipeline multiplied raw magnitudes (`result *= m`) with no channel grouping, and `apply_instant_modifiers` did `base_value *= magnitude`, so an Instant `Multiply` of `0` zeroed the attribute instead of acting as the identity. It now groups by `Channel`, applies `(1 + Σm)` per channel, and treats channel-less modifiers as singletons. The skill's `SKILL.md` pipeline summary, `references/schemas.md`, `references/simulation-config.md` (including an example that authored `value: 1.5` for "50% more armor"), and audit-checklist guidance are corrected to match.

Two further simulator conformance bugs, found while reviewing the above, are fixed in the same pass:

- **Stacked effects expired incorrectly.** Modifier ownership was tracked by the list index recorded at application time, and the function meant to re-sync those indices after a removal was an empty stub. Once any effect expired, every other effect's recorded indices were stale: with three timed `Add` effects on one attribute, one expiry removed nothing and another removed the wrong effect's modifier, leaving the attribute permanently wrong. Entries are now tagged with their owning effect's name and removal filters on that name, so stacked effects may expire in any order. `Override` is likewise owner-tracked, so an expiring override correctly falls back to a still-active one (§5.3 LIFO tie-break).
- **Periodic `Multiply` was written to the Base Value every tick.** Periodic executions routed through the Instant path, applying every operation to the base and compounding the result each tick — so a periodic `Multiply` authored as `+0.10` drove an attribute 100 → 10 → 1 → 0.1 toward zero (the released code multiplied by the raw magnitude), permanently and surviving expiry. §5.2 requires periodic executions to apply only `Add` / `AddPost` / `Override` to the base, precisely to avoid that compounding. A periodic durational effect now writes only those three to the Base Value on each execution, while its `Multiply` modifiers are registered as Current-Value modifiers for the effect's lifetime and withdrawn on expiry — so the percentage applies for as long as the effect is active, without accumulating and without being dropped.

Finally, drops a `Divide` modifier reference in §5.2 (and in the pending Instant-Multiply changeset) that contradicted §9.4.1's "there is no `Divide` operation", repairs a stray blank line that broke the §9.4 doc comment mid-list, and updates the `docs-site` landing-page formula, which still rendered the defunct pipeline with an "additive %" stage and a raw-factor "true mult" term.
