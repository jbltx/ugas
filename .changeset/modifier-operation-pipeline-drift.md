[Fixed] Schemas + spec — the `Modifier.Operation` description in `gameplay_effect.json`/`.yaml` contradicted the normative pipeline on two counts. It described `Multiply` as a "multiplicative factor" taking a "reciprocal magnitude (e.g. `0.5`)" to stand in for a Divide operation, but `Multiply` uses the §5.3 signed-bonus convention where the channel factor is `(1 + Σm)` — so `0.5` is a *+50% bonus*, and a consumer following the description to halve an attribute would have increased it by 50% instead. §9.4.1 already specified `−0.5` for a 50% reduction. The description now states the signed-bonus convention explicitly and gives the `−0.5` example. It also carried a stale 8-step pipeline numbering (`Multiply` 6, `AddPost` 7, `Override` 8) that disagreed with the normative §5.3 Order of Operations and the §9.4.1 table, both of which say 4/5/6; the schemas and the §9.4 TypeScript doc comment now match. The enum values themselves were correct and are unchanged. Also removed a reference to a `Divide` modifier in §5.2 that contradicted §9.4.1's "there is no `Divide` operation", and repaired a stray blank line that broke the §9.4 doc comment mid-list.
