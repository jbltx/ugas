[Added] Asynchronous-validation lifecycle state for Gameplay Abilities (§8.8), resolving the activation/validation race condition. Introduces an explicit `PendingConfirmation` state in the §8.2 lifecycle, sitting between `Activating (Validating)` and `Commit`, for an activation that has passed the synchronous §8.3 checks but whose authoritative outcome is still outstanding pending asynchronous validation (server-side anti-cheat, remote-inventory check, or premium-consumable entitlement/auth). While in `PendingConfirmation` an activation has NOT committed: no cost or cooldown is consumed, `ActivationOwnedTags` are not granted, and it is not executing authoritative Tasks. Defines two coordinated paths. Path A (server-authoritative, no prediction): a §8.3-passing async ability enters `PendingConfirmation` before Commit; async success proceeds to Commit -> Active, async failure (or timeout) transitions Fail -> `Granted` with nothing consumed. Path B (client-side prediction): the owning client predictively commits and enters a *speculative* Active carrying a `PredictionKey` (§13.8) while the authoritative server holds `PendingConfirmation` until validation resolves — `ConfirmPrediction(key)` confirms the predicted commit with no visible change; `RejectPrediction(key)` rolls the speculative activation back via the §13.5 reconciliation path (restoring the §13.8.3 `CaptureState()` snapshot) and returns the ability to `Granted`. This gives the late-rejection race a modeled transition instead of an undefined one. Also specifies §8.6 cancellation while pending (no cost/cooldown consumed; in-flight async validation SHOULD be aborted and late results MUST be discarded) and binds a speculative-Active to the §13.8.2 prediction window (a client MUST NOT stay speculatively Active past the window awaiting confirmation). Updates the §8.2 ASCII state diagram to show the new state, the sync-only `Validating -> Commit` bypass, the predicted-Active vs authoritative-pending distinction, and the reject -> rollback -> `Granted` edge. Adds an optional `AsyncValidation` marker (`Required` / `Kind` / `TimeoutMs` / `Predicted`) to the §8.7 ability schema documentation to flag abilities that route through `PendingConfirmation`.

Additive and documentation-only; cross-references §13.5, §13.7, and §13.8 without modifying them, and does not renumber existing sections. Closes #7.
