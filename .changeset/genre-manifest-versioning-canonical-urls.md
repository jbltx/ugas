[Added] Genre pack + entity manifest, a versioning contract, and canonical resolvable schema URLs (P1 of the Unity Studio integration feedback):

- **`{version}/genres/index.json`** — per pack: `id`, `title`, `scope`, `signatureMechanic`, `specPath`, and an `entities[]` list (each with `id`, `type`, `path`); multi-document entity files expand to one entry per document. Generated by `scripts/build_genre_manifest.py` from a new structured `genres/<pack>/pack.yaml` per pack. Consumers can now enumerate packs and load their template entities deterministically instead of scraping `llms-full.txt`.
- **`versions.json`** now follows a stable contract — `{ latest, versions: [{ version, status, released, changelog }] }` — regenerated deterministically from the published version directories (dates preserved across the legacy → new shape).
- [Changed] **Canonical schema identity moved to `https://ugas.jbltx.com/<version>/schemas/<type>.json`.** Each JSON schema's `$id` now equals its resolvable fetch URL (was an unversioned, non-resolvable `github.com/...` URL), and every stamped `$schema` in examples, genre entities, and spec prose uses the same host (was `raw.githubusercontent.com`). `$id`/`$schema` now agree.
- **Meta-schemas** `schemas/manifest/genres-index.schema.json` and `versions.schema.json` describe the new manifests.
- [Fixed] Genre `.adoc` headers pinned `v1.0.0-draft.1` while the package was `draft.4`; `scripts/sync_version.py` now keeps every genre doc's `:revnumber:`/`:ugas-version:` in sync with `package.json`, and a new `scripts/check_version_consistency.py` CI guard fails on placeholder leakage (a concrete version baked into a source `$schema`/`$id`) and on genre-header drift.
